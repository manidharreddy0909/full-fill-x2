# FULFILL-X — WebSocket Specification

## 1. Purpose

Define every real-time event in FULFILL-X: what triggers it, what its
payload contains, which frontend components consume it, and what 3D effect it causes.

WebSocket is the primary real-time channel. Polling is a fallback.

---

## 2. Connection

```
URL: ws://{host}/ws/{client_id}
Protocol: Standard WebSocket (RFC 6455)
Client ID: UUID, generated by frontend on connection
Reconnection: Auto with exponential backoff (1s, 2s, 4s, 8s, max 30s)
```

### Handshake

On connection, server sends:
```json
{
  "type": "connection.ready",
  "payload": {
    "server_time": "ISO-8601",
    "world_snapshot_id": "uuid",
    "active_signals": 7,
    "active_scenario_id": "uuid | null"
  }
}
```

---

## 3. Event Schema

All events follow this envelope:

```typescript
interface WSEvent<T> {
  type: string          // event name
  payload: T            // event-specific data
  timestamp: string     // ISO-8601
  source: string        // "system" | "agent:{id}" | "orchestrator"
  run_id?: string       // agent pipeline run ID (if applicable)
}
```

---

## 4. World Events

### `world.update`

| Field | Value |
|-------|-------|
| **Trigger** | Any mutation to world state (plan approved, signal ingested) |
| **Source** | `WorldModelEngine` |
| **Consumers** | Command Center (KPI refresh), 3D WorldScene |
| **3D Effect** | Node color lerp to new risk scores (400ms); edge load update |

**Payload**:
```typescript
{
  snapshot_id: string
  network_health_score: number
  changed_node_ids: string[]          // only changed nodes
  changed_edge_ids: string[]
  nodes: WorldNode[]                  // updated nodes only
  edges: WorldEdge[]                  // updated edges only
  is_full_refresh: boolean            // true on seeding, false on incremental
}
```

## 5. Signal Events

### `signal.detected`

| Field | Value |
|-------|-------|
| **Trigger** | Signal ingested via SignalIngestor |
| **Source** | `SignalIngestor` |
| **Consumers** | Signal Intelligence (prepend to list), Command Center (signal feed) |
| **3D Effect** | Flash at affected nodes (white pulse, 1s); signal icon appears |
| **UI Effect** | Toast notification if CRITICAL; signal count badge increments |

**Payload**:
```typescript
{
  signal: {
    id: string
    type: SignalType
    severity: SignalSeverity
    confidence: number
    title: string
    affected_node_ids: string[]
    detected_at: string

```

### `signal.resolved`

| Field | Value |
|-------|-------|
| **Trigger** | Signal marked RESOLVED |
| **Consumers** | Signal Intelligence, Command Center |
| **3D Effect** | Signal icon fades out at affected nodes |

## 6. Risk Events

### `risk.update`

| Field | Value |
|-------|-------|
| **Trigger** | After any signal ingest, signal resolution, or plan approval |
| **Source** | `RiskEngine` |
| **Consumers** | Risk Explorer, Command Center, 3D WorldScene |
| **3D Effect** | All nodes lerp to new risk colors (400ms each) |

**Payload**:
```typescript
{
  computed_at: string
  network_health_score: number
  changed_nodes: Array<{
    node_id: string
    risk_scores: NodeRiskScores
    delta: NodeRiskScores  // change from previous
  }>
}
```

### `risk.propagated`

| Field | Value |
|-------|-------|
| **Trigger** | After each propagation hop in RiskEngine |
| **Source** | `RiskEngine.propagate()` |
| **Consumers** | 3D WorldScene only |
| **3D Effect** | Disruption wave emanates from each newly-affected node (per hop) |
| **Purpose** | Enables animated risk wave visualization |

**Payload**:
```typescript
{
  hop: number             // 0 = direct, 1 = first propagation, etc.
  node_ids: string[]      // nodes newly affected at this hop
  risk_scores: { [node_id: string]: NodeRiskScores }
}
```

|-------|-------|

| **Source** | `AgentOrchestrator` |
| **Consumers** | Agent War Room (card status → RUNNING) |
| **3D Effect** | Agent orbit icon appears at relevant nodes (pulsing) |

**Payload**:
```typescript

  agent_id: string     // "inventory" | "supplier" | etc.
  agent_name: string
  run_id: string
  started_at: string
}
```

### `agent.proposal`

| Field | Value |
|-------|-------|
| **Trigger** | Agent completes (proposal or failure) |
| **Source** | Agent (via orchestrator) |
| **Consumers** | Agent War Room (card status → COMPLETE / FAILED / TIMEOUT) |
| **3D Effect** | Action particles: reorder beams, reroute lines |

**Payload**:
```typescript
{
  agent_id: string
  run_id: string
  status: "PROPOSED" | "INFEASIBLE" | "TIMEOUT" | "AI_ERROR"
  proposal?: {
    objective: string
    reasoning: string        // condensed, ≤ 200 words
    evidence: string[]
    actions: ProposalAction[]
    confidence: number
    feasibility_score: number
  }
  completed_at: string
  duration_ms: number
}
```

### `coordinator.updated`

| Field | Value |

## 12. System Events

### `connection.ready`

**Trigger**: Initial WebSocket connection established.

### `connection.heartbeat`

**Trigger**: Server every 30s.
**Payload**: `{ server_time, active_connections }`.
Frontend must respond within 10s or connection is dropped.

### `system.provider_switched`

**Trigger**: POST /api/system/providers/switch.
**Consumers**: System Status screen; global header badge.

## 13. Frontend WebSocket Implementation

```typescript
// WebSocketContext.tsx

export const WebSocketProvider: React.FC<{ children: ReactNode }> = ({ children }) => {
  const clientId = useRef(crypto.randomUUID())
  const wsRef = useRef<WebSocket | null>(null)
  const [status, setStatus] = useState<"connecting" | "connected" | "disconnected">("connecting")
  const { setWorldSnapshot, setRiskMap, addSignal, addAgentProposal } = useWorldStore()
  const queryClient = useQueryClient()

  const handleMessage = useCallback((event: MessageEvent) => {
    const wsEvent: WSEvent<unknown> = JSON.parse(event.data)
    switch (wsEvent.type) {
      case "world.update":
        setWorldSnapshot(wsEvent.payload)
        queryClient.invalidateQueries({ queryKey: ["world"] })
        break
      case "risk.update":
        setRiskMap(wsEvent.payload)
        queryClient.invalidateQueries({ queryKey: ["risks"] })
        break
      case "signal.detected":
        addSignal(wsEvent.payload.signal)
        queryClient.invalidateQueries({ queryKey: ["signals"] })
        break
      case "agent.proposal":
        addAgentProposal(wsEvent.payload)
        break
      case "plan.ranked":
        queryClient.invalidateQueries({ queryKey: ["plans"] })
        break
      // ... all other events
    }
  }, [])

  // Reconnect logic with exponential backoff
  const connect = useCallback(() => {
    const ws = new WebSocket(`ws://${host}/ws/${clientId.current}`)
    ws.onmessage = handleMessage
    ws.onclose = () => {
      setStatus("disconnected")
      scheduleReconnect()
    }
    wsRef.current = ws
  }, [handleMessage])
}
```

## 14. Fallback: Polling Mode

When WebSocket is disconnected, the frontend falls back to polling:
- `GET /api/world` every 5s
- `GET /api/risks` every 10s
- `GET /api/signals` every 10s

Polling is clearly indicated in the WebSocket status indicator (amber color).
